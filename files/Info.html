Zerodha Kite
Trading Platform Clone

Production-grade simulation of the Zerodha Kite trading platform — live NSE/BSE market data, realistic order execution, options paper trading, and a matching React Native mobile app.

Node.js + Express MongoDB React React Native / Expo Socket.IO · Real-time NSE · Dhan · Yahoo Finance

Project Overview

This project is a full-featured clone of the Zerodha Kite trading platform — India's largest retail stock broker. It simulates the complete trading lifecycle: market data ingestion, order placement and execution, portfolio management, P&L accounting, options paper trading, and fund management — with realistic Zerodha-style brokerage charges.

Target Users

  • Developers learning full-stack development with a real-world domain
  • Finance students practicing equity and F&O trading without real capital
  • Portfolio builders showcasing MERN + React Native skills

Problem It Solves

Paper trading platforms either use fake data or strip away the complexity of real market mechanics. This project uses live NSE prices (via NSE India → Dhan → Yahoo Finance fallback chain), applies real Zerodha brokerage schedules (STT, exchange charges, GST, stamp duty), enforces T+1 settlement rules, and models intraday auto-squareoff — giving a realistic feel without real money at risk.

Data Flow

  1. Market data service polls NSE India (indices) and Dhan (stock LTPs) every second via WebSocket, with REST fallback every 15s.
  2. Every 30s the backend broadcasts the complete price map + index data to all connected clients via Socket.IO marketData event.
  3. Client dashboards/mobile screens subscribe to marketData and update LTPs in-memory without re-fetching REST.
  4. On order placement, the REST route validates margin, calls the Order Engine, which mutates Holdings/Positions/Wallet atomically and broadcasts an orderExecuted Socket.IO event.
  5. LIMIT/SL/SL-M orders are saved as PENDING and evaluated against the live price map on every market-data tick — no polling needed.
  6. EOD cron (3:45 PM IST on weekdays) squares off all open MIS positions at last LTP, archives trades into PLRecords, and resets intraday state.

Order Engine (orderEngine.js)

The order engine is the most critical module — it handles all equity order execution, position/holding mutations, and margin accounting. Every order flows through it via two paths:

  • MARKET orders: executeOrder() is called immediately on placement. The order is atomically executed: trade recorded, holdings/positions mutated, wallet recomputed, Socket.IO broadcast fired.
  • LIMIT / SL / SL-M orders: Saved as PENDING in MongoDB. On every market-data tick, evaluatePendingOrders() scans all pending orders and checks trigger conditions against the current price map. Matching orders call executeOrder().

Margin accounting is always recomputed fresh from source-of-truth collections — never tracked incrementally. usedMargin = sum of CNC holding cost basis; misMargin = MIS notional / leverage; blockedMargin = pending BUY notional. This eliminates drift bugs common in incremental approaches.

CNC (Delivery) Fill Logic

  1. BUY: upsert HoldingsModel with quantity-weighted average price. Freshly bought quantity is added to t1Quantity field — can't be sold until T+1 BOD prep.
  2. SELL: validate quantity ≤ holding.quantity - t1Quantity (T1 sell protection). Compute realized P&L = (execPrice − avgPrice) × qty. Reduce holding quantity; delete doc if quantity reaches zero.
  3. Recompute wallet: sum all holding cost bases → usedMargin; update availableMargin.

MIS (Intraday) Fill Logic

MIS supports genuine long and short positions — quantity is signed (positive = long, negative = short). On a BUY against an existing short, the engine nets the positions and books a ClosedPosition snapshot for the closed-out quantity. MIS positions are auto-squared-off at EOD.

Cover Orders

A cover order is a pair: an immediate MARKET BUY + a compulsory SL-M SELL leg. The SL-M leg is linked via linkedOrderId. If the MARKET leg fills, the SL-M leg remains PENDING protecting the position. Cover orders cannot be cancelled independently — only by squaring off the entire position.

Basket Orders

A basket bundles multiple order legs (stored in BasketModel). On execute, each leg is submitted through the normal order flow sequentially. MARKET legs fill immediately; LIMIT/SL legs rest as PENDING. If any leg is rejected, earlier filled legs are NOT reversed — partial fills are accepted.

Market Data Service (marketDataService.js)

A 4-tier fallback chain ensures live prices are available even when upstream services are down:

Tier Source Data Frequency
1st NSE India (allIndices API) Index LTPs, change % On every 30s broadcast cycle
2nd Dhan HQ WebSocket + REST Stock LTPs (50+ NSE symbols) 1s push via WS; 15s REST fallback
3rd Yahoo Finance 2 (Node.js) All stocks + indices On Dhan failure
4th Simulated (random walk) All symbols Always available offline

The service maintains an in-memory price map keyed by symbol. Each entry carries: ltp, open, high, low, prevClose, change, changePercent, volume, high52w, low52w, source.

Charges Service (chargesService.js)

Realistic Zerodha 2024–25 brokerage schedule — not a flat percentage. The service accepts { segment, side, turnover } and returns a full charge breakdown:

Segment Brokerage STT Exchange Special
equity_delivery ₹0 (zero) 0.1% both sides 0.00297% ₹15.34 DP charge on sell
equity_intraday 0.03% or ₹20 cap 0.025% sell only 0.00297% —
options ₹20 flat per order 0.1% sell premium (post Oct-2024) 0.03503% —
futures ₹20 flat per order 0.02% sell only 0.0019% —

GST at 18% is applied on brokerage + exchange charges + SEBI charges. Stamp duty applies on buy side only, at segment-specific rates.

Features — Detailed

Orders & Execution

Order Types

  • MARKET: Executes immediately at the current LTP from the price map. No price negotiation.
  • LIMIT: Saved as PENDING. BUY limit fills when LTP ≤ limitPrice; SELL limit fills when LTP ≥ limitPrice.
  • SL (Stop Loss): Has both a trigger price and a limit price. When LTP ≤ triggerPrice (for BUY SL), the order becomes an active LIMIT order at limitPrice. Used when you want a guaranteed limit after the trigger fires.
  • SL-M (Stop Loss Market): Executes at market price once trigger is crossed. Faster than SL but may get a worse fill.

Product Types

  • CNC (Cash & Carry): Delivery. Shares credited to demat. No auto-squareoff. Zero brokerage on Zerodha schedule.
  • MIS (Margin Intraday Square-off): Intraday only. Supports long and short. Auto-squared off at 3:15 PM IST. 5× leverage modelled.
  • NRML: Used for F&O (options/futures) — overnight positions allowed in derivatives.

Portfolio & P&L

Holdings P&L

Unrealized P&L = (ltp − avgPrice) × quantity. The dashboard updates ltp from Socket.IO marketData events in real-time so the P&L value animates live. Realized P&L is booked on each SELL fill and accumulated in PLRecords.

Day P&L

The Positions screen aggregates realized + unrealized P&L for all positions opened today. Closed (squared-off) positions show the frozen ClosedPosition snapshot — the P&L never recomputes after the position is closed, so "what you booked" is immutable.

Profit & Loss Statement

The P&L screen reads from PLRecords — a permanent archive of every realized trade grouped by day, symbol, and segment. Supports filtering by segment (equity/fno/combined) and arbitrary date ranges. The monthly breakdown groups records by calendar month, showing realized P&L, total charges, and net P&L. PDF export via jspdf-autotable is supported.

T+1 Settlement

Shares bought with CNC go into t1Quantity. The BOD cron (9:00 AM next trading day) clears t1Quantity, making them sellable. Attempting to sell T1 shares triggers an OrderRejectedError with a clear message.

Options Paper Trading

NIFTY 50, BANK NIFTY, SENSEX, NIFTY IT, FINNIFTY all have a live option chain. Expiries are computed dynamically (weekly for NIFTY/BANKNIFTY, monthly for others). The chain shows CE and PE strikes at ±10% of the current underlying price in 50-point intervals.

  • Premiums: Black-Scholes approximation using live underlying LTP, strike, expiry, and implied volatility estimated from historical price range.
  • Lot sizes: NIFTY=75, BANKNIFTY=15, SENSEX=10 (real NSE lot sizes).
  • Margin: Premium × lots × lotSize is debited from optionMargin on buy. Written (short) positions use an approximation margin.
  • Square-off: Via POST /optionPositions/:id/squareoff. Partial squareoff by specifying lots.

GTT (Good Till Triggered) & Alerts

GTT extends a price alert into an automatic order trigger. When the alert condition fires:

  1. The market-data broadcast loop checks all active GTT alerts against current LTP.
  2. If condition === 'ABOVE' && ltp >= targetPrice (or BELOW), the GTT fires.
  3. A LIMIT order is placed at limitPrice for quantity shares on the specified side.
  4. The GTT is deactivated (active: false, triggered: true), so it never fires twice.
  5. An alertTriggered Socket.IO event is emitted and a local OS notification is fired on mobile.

OCO (One Cancels Other): Two trigger levels on one GTT. Whichever leg fires first executes its order and deactivates the entire GTT (the other leg is killed). Used for "buy on breakout above ₹X or buy on dip to ₹Y" strategies.

Funds & Wallet

Single-wallet model (single user, demo). Deposit via POST /funds/deposit increments balance and recomputes availableMargin. Withdrawal validates availableMargin ≥ amount to prevent overdraft. Each transaction is ledgered in FundTransactions with method (UPI/NETBANKING/BANK) and a reference number for traceability.

Live Chat

Persistent Socket.IO chat room. Messages are saved to ChatModel and broadcast to all connected clients. On connection, the last 100 messages are fetched via GET /chat/history so the room is pre-populated. The mobile app uses a keyboard-avoiding view and auto-scrolls to the newest message.

Corporate Actions

A curated CorporateActions collection tracks dividends, splits, and bonus issues. POST /corporate-actions/apply applies pending actions to holdings: dividends credit the wallet, splits/bonuses multiply quantity and adjust avgPrice proportionally. The applied flag makes the operation fully idempotent.

API Client (src/api/client.js)

Thin fetch wrapper with:

  • Short-TTL cache: Hot GETs (/market/live, /market/indexes) are cached for 2s and de-duplicated in-flight — prevents N parallel component mounts from firing N identical requests.
  • Socket.IO singleton: getSocket() returns one shared instance with websocket + polling transports and infinite reconnect. Polling fallback ensures connectivity on mobile carrier NATs.
  • URL resolution: EXPO_PUBLIC_API_URL env var → Constants.expoConfig.extra.apiUrl → hardcoded LAN IP for local dev.

Auth Flow

  1. App.js restores AsyncStorage session flag on mount. Shows a spinner during restore to prevent flash-of-login-screen for already-signed-in users.
  2. LoginScreen validates credentials and calls onLogin().
  3. handleLogin() writes 'session_active': '1' to AsyncStorage before flipping React state — guards against OS backgrounding the app during the write window.
  4. AuthContext provides logout() to any screen without prop-drilling through stacks.

Market Hours Utility

Uses pure UTC-offset arithmetic (+5.5h) rather than toLocaleString('en-IN', {timeZone:'Asia/Kolkata'}) followed by new Date(string). The re-parsing path breaks on Hermes builds that don't ship full ICU timezone data — silently returns NaN, making the market look permanently closed.

Background Jobs & Scheduled Tasks

Implemented via node-cron in index.js. All crons operate in IST (UTC+5:30) computed via plain UTC-offset arithmetic.

Cron Schedule Action
Market Data Broadcast Every 30s (setInterval) Calls fetchAllStockPrices() then broadcasts marketData Socket.IO event to all connected clients.
Dhan LTP (Fast tick) Every 1s via WebSocket Dhan pushes live LTP for subscribed symbols. The price map is updated in memory; broadcast waits for 30s cycle.
Dhan Quote (REST) Every 15s Fetches full quote (OHLC, volume) for all tracked symbols when Dhan WS doesn't carry that data.
BOD Prep 9:00 AM IST, Mon–Fri Clears t1Quantity on all holdings (T+1 settlement). Restores buying power for yesterday's purchases.
EOD Squareoff 3:15 PM IST, Mon–Fri Squares off all open MIS equity positions at last LTP. Archives their trades into PLRecords. Clears intraday P&L state.
EOD Archive 3:45 PM IST, Mon–Fri Rolls up unarchived trades into permanent PLRecord documents. Sets archived: true on processed trades to prevent double-counting on restarts.
Alert/GTT Evaluation On every marketData broadcast Scans all active PriceAlertModel docs. Fires GTT orders or emits alertTriggered when conditions are met.
Pending Order Eval On every marketData broadcast evaluatePendingOrders() checks LIMIT/SL/SL-M orders against current price map. Executes matching orders.

Security

Demo mode: This is a single-user simulation. No user authentication is enforced on REST endpoints. In a production deployment, all routes would require a signed JWT and user-scoped data isolation.

What's in place

  • CORS: cors() middleware allows all origins (demo). Production should whitelist specific domains.
  • Input validation: All API handlers validate required fields and return structured 400 errors. Symbol inputs are always .toUpperCase()'d before DB queries to prevent case-mismatch injections.
  • Mongoose schema validation: enum constraints on critical fields (type, side, status, productType) reject invalid values at the ORM layer before reaching the order engine.
  • Dhan token: 24-hour JWT stored in MongoDB (not in env files). Refreshed via POST /admin/update-token — the token is never exposed to client-side code.
  • Mobile session: Session flag stored in AsyncStorage (device-local). AuthContext.logout() removes it and returns to LoginScreen.
  • T1 sell protection: Order engine validates sellable = quantity − t1Quantity — prevents fraudulent T1 sell attempts that would bypass settlement rules.
  • Margin check: availableMargin ≥ required validated before any BUY order is saved. Rejection creates an REJECTED order doc with rejectionReason for audit trail.

Performance & Optimization

  • In-memory price map: All 50+ stock prices live in a Node.js Map object — O(1) lookups on every tick, zero DB reads for price data.
  • Fresh-recompute margin: Rather than incrementally tracking usedMargin (which drifts under concurrent fills), the engine recomputes it from the live holdings collection on every fill. Slightly more DB reads per trade, eliminates an entire class of balance bugs.
  • Client-side caching (mobile): cachedGet() with 2s TTL collapses concurrent requests from multiple components mounting simultaneously. _inflight map de-duplicates in-flight requests — two components requesting /market/live at t=0ms resolve from the same promise.
  • PLRecord index: { tradeDate: 1, segment: 1 } compound index on PLRecords enables fast date-range + segment queries without full collection scans.
  • Lazy screen loading (mobile): React.lazy() + Suspense defers parsing of heavy screens (option chain, charts) until first navigation — reduces cold-start JS parse time.
  • Socket.IO polling fallback: transports: ['websocket', 'polling'] allows upgrade from long-polling → WS. Prevents silent disconnects on mobile carrier NATs that block raw WebSocket upgrades.
  • Dhan WebSocket LTP: 1-second push ticks from Dhan avoid polling entirely for price updates. The 30s broadcast cycle is for connected clients — the in-memory map is always fresh.

Edge Cases & Error Handling

Scenario Handling
Market closed + MARKET order Allowed (demo mode simulates immediate fill). Real behavior: rejected outside 9:15 AM – 3:30 PM IST.
Insufficient margin on BUY OrderRejectedError → order saved as REJECTED with rejectionReason. Specific ₹amount shown in error message.
T1 sell attempt OrderRejectedError stating how many shares are unsettled and until when.
SELL more than held Rejected with "you only hold N shares" message. Naked shorting blocked for CNC.
Dhan API down Automatic fallback to Yahoo Finance. Stats object tracks source field; /market/status reports the active source.
All data sources down Simulated prices (random walk on last known LTP) — trades still process, users see a "SIMULATED" badge in market status.
Dhan JWT expired POST /admin/update-token refreshes without restart. tokenService caches token in memory; stale cache expires after 30 min.
Socket.IO disconnect Infinite reconnect with exponential backoff (1s → 5s max). On reconnect the client receives a fresh marketData broadcast immediately.
Mobile iOS timezone (Hermes) marketHours.js uses pure UTC arithmetic — never toLocaleString + new Date(string), which silently returns NaN on Hermes without full ICU.
EOD archive restart during cron Trades have archived flag. EOD cron only processes { archived: false } trades — idempotent across restarts.
GTT double-trigger active: false set atomically before the order is placed. Alert evaluation loop skips inactive alerts — can never fire twice.
Basket partial failure Filled legs are NOT reversed (no saga/compensating transactions). REJECTED legs save with rejectionReason. Documented behavior.
React Native app crash ErrorBoundary wraps the entire app tree. Catches render errors, shows recovery UI instead of white screen.
